## Минимальная бесплатная схема

GitHub Pages → Cloudflare Worker на workers.dev + Turnstile + D1 → подписанный запрос к Apps Script → запись в Google Sheet → Telegram outbox.

Без Worker прямой публичный Apps Script с анонимным doPost может обходить клиентские проверки. CORS не защита от ботов. Worker проверяет происхождение, 8 КБ тела, типы/длины, контакт, обязательное согласие и версию политики, honeypot, серверный Turnstile с hostname/action. D1 атомарно ограничивает 5 запросов/IP/10 минут и 100 общих/10 минут. Окна фиксированные: на границе возможно удвоение квоты. Общие IP могут давать ложные ограничения. Cloudflare доверенно задаёт CF-Connecting-IP; не принимать подставляемый X-Forwarded-For.

В D1 нет исходных полей заявки или IP: только HMAC IP, HMAC содержания, UUID, статусы и время. Хэши — псевдонимные данные, включить в уведомление. Очистка cron ежедневно: rate buckets ~20 минут + до суток до cron, receipts 7 дней + до суток. При изменении HASH_SECRET старые digest становятся несовместимы с повтором; менять по плану с отключённым приёмом. Доступ к D1 и аккаунту Cloudflare ограничить владельцем.

Free: Workers, Turnstile и D1 имеют бесплатные квоты; ресурсы не созданы. Не выбирать paid plan/автоматическое повышение тарифа. При исчерпании квот отдавать ошибку, не обходить защиту. Объём D1 и Apps Script quotas контролировать владельцу. Полной DDoS-защиты или гарантии доставки схема не обещает: публичный Apps Script даже с HMAC может получать мусор и расходовать квоты. HMAC предотвращает неавторизованную запись, но не исчерпание квот Google.

## Контракт Worker → Apps Script и честное подтверждение

JSON: {timestamp: unix seconds, payload: JSON string, signature: hex HMAC-SHA256(timestamp + '.' + payload)}. payload: requestId UUID, name, contact, city, job, consent:true, privacyVersion. Окно подписи 5 минут; секрет только у серверов. Нельзя просто подключить существующий test handler без проверки этого контракта.

Apps Script проверяет HMAC, возраст запроса, поля и политику повторно. Под ScriptLock проверяет UUID и fingerprint (contact+city+job); одинаковая заявка подавляется 24 часа даже с новым UUID. UUID строки хранится до удаления самой заявки. Разная заявка с тем же UUID отклоняется; в Worker digest проверяет все поля. Все пользовательские значения пишутся с префиксом апострофа как литералы, включая = + - @. При экспорте и повторном импорте CSV нельзя снимать текстовую защиту; не использовать сырые данные в формулах.

Только после appendRow + SpreadsheetApp.flush() адаптер возвращает {saved:true,requestId}. Ошибка/timeout не означает, что записи нет; кандидат должен повторить с теми же данными и UUID. UI удерживает UUID в памяти на время страницы, не хранит PII в localStorage/sessionStorage. После перезагрузки fingerprint на сервере защищает от повторов. Worker дополнительно сохраняет подтверждённые квитанции 7 дней. Параллельные POST окончательно дедуплицируются ScriptLock в Google; локальный D1 сам по себе не гарантирует exactly-once запись в Google.

Apps Script ContentService может вернуть redirect на script.googleusercontent.com: Worker следует только проверенному HTTPS-домену без передачи подписанного тела в GET. HTML вместо JSON, неверный requestId, отрицательная квитанция и timeout не дают успеха. Персональные данные и содержимое исключений не логируются.

## Telegram временно недоступен

В той же строке Sheet сохраняется pending и attempts. Сохранение заявки успешно независимо от уведомления. Retry-триггер обрабатывает не более 10 строк за вызов и до 10 попыток на строку. После 10 попыток нужен ручной разбор/сброс attempts, мониторинг выполняет владелец по таблице. Доставка Telegram at-least-once: при сбое после принятия сообщения, но до отметки sent возможно повторное уведомление; UUID в сообщении позволяет его распознать. Фиктивного обещания exactly-once нет. Бот не используется как источник истины.

## Хранение и удаление

До запуска владелец должен организовать удаление заявок старше 6 месяцев (и раньше по отзыву) из Sheet, Telegram, выгрузок и резервных копий. Код предложения не удаляет данные существующей системы автоматически. Для Telegram проверить доступный срок автоудаления группы, не превышающий утверждённый срок; не рассчитывать на возможность бота удалить любое старое сообщение. Доступ участников, скриншоты/выгрузки и резервные копии требуют отдельного процесса. Если невозможно соблюдать срок для полных данных в Telegram, согласовать уведомления только с UUID и защищённой ссылкой на Sheet. Cron D1 не удаляет данные Google/Telegram.
