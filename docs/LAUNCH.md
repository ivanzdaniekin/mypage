# Завершение интеграции: инструкция владельцу

## Что подготовлено, что не проверено в Google

Полный файл для замены: **backend/Code.gs**. Не объединять с прежним фрагментом AppsScriptAdapter.gs (он устарел). Имена sendTelegram, saveLead, testLead, doPost и testDoPost сохранены, но старые небезопасные семантики сознательно изменены: doPost принимает только подписанный JSON, saveLead требует согласия/UUID/версии, Telegram обрабатывается отдельной очередью. Существующие внешние вызовы старых сигнатур потребуют адаптации. Полный исходник прежнего проекта не предоставлен — совместимость с неизвестными функциями обещать нельзя. Схема Лист1 A:G сохранена.

Реальные Apps Script, Worker, Google Sheets и Telegram **не изменены и не тестировались в сети**: endpoint не предоставлен; отправка в Telegram требует отдельного подтверждения. Онлайн проверена документация Google Web Apps/ContentService. Локально реальный исходник Worker подписывает запрос, полный Code.gs его проверяет в сервисном harness; это проверка совместимости кода, НЕ подтверждение работы развёрнутого сервиса. Конкурентные тесты моделируют LockService/контеншн, не заменяют тест параллельных облачных исполнений.

## 2. Apps Script: что нажать

1. Сначала сохранить резервную копию текущего Code.gs и конфигурации развёртывания. В Google Таблице: Расширения → Apps Script. Не пересылать токены и не коммитить резервную копию Properties.
2. Для первого теста использовать отдельную синтетическую таблицу с листом **Лист1**, A:G: Дата и время | Имя | Телефон / Telegram | Город | Интересующая работа | Источник | Статус. В production эти семь столбцов не переставлять/не расширять.
3. После согласования заменить содержимое Code.gs целиком файлом backend/Code.gs, удалить/отключить старые дубли doPost в других файлах. Включить V8, сохранить. Никаких новых HTTP-заголовков в e не предполагается.
4. Настройки проекта → Свойства скрипта → добавить свойства из таблицы ниже. По умолчанию оба флага приёма и уведомлений false. LEADS_TEST_MODE оставить disabled.
5. Выполнить **setupMypage** вручную, авторизовать доступ Google по подсказкам. Он создаст только отдельный лист **MypageJournalV2**, не меняя Лист1. Не запускать testLead/testDoPost/retryTelegram без разрешения теста.
6. Развернуть → Новое развёртывание → тип Веб-приложение → Выполнять от моего имени → Доступ Anyone. Эта настройка делает URL доступным, но подписанный приём остаётся выключен. Сохранить URL /exec. Если тип доступа недоступен из-за политики Workspace — остановиться, не обходить ограничения.
7. Для обновлений: Развернуть → Управление развёртываниями → карандаш → Новая версия → Развернуть. /dev не использовать в Worker.

| Script Property | Значение/назначение |
|---|---|
| MYPAGE_ENABLED | false до теста; флаг публичной записи |
| MYPAGE_NOTIFICATIONS_ENABLED | false до отдельного разрешения отправки Telegram; независим от приёма |
| MYPAGE_ALLOW_PROBE | true временно для подписанного read-only probe, затем false |
| MYPAGE_SHEET_ID | ID тестовой/позже действующей таблицы (не URL) |
| MYPAGE_SIGNING_SECRET | Новый случайный серверный секрет не менее 32 байт, тот же в Worker SIGNING_SECRET |
| MYPAGE_PRIVACY_VERSION | Та же утверждённая версия политики, что в Worker/форме; для синтетики отдельная тестовая версия |
| TELEGRAM_BOT_TOKEN | Существующее секретное свойство; не выводить/не менять без необходимости |
| MYPAGE_TELEGRAM_CHAT_ID | Сначала тестовая закрытая группа; действующая -5325144321 только после подтверждения |
| LEADS_TEST_MODE | disabled; старые ручные тесты не выполняются автоматически |
| MYPAGE_ALLOW_SYNTHETIC_TEST | false; только для отдельно разрешённых ручных тестов testLead/testDoPost |

При отсутствии MYPAGE_SHEET_ID код пробует bound spreadsheet, но Web App может не иметь active spreadsheet — для Web App обязательно задайте ID. Значение MYPAGE_ENABLED=false блокирует запись независимо от клиента; MYPAGE_NOTIFICATIONS_ENABLED=false останавливает очередь отдельно. Старые неподписанные маршруты и развёртывания нельзя оставлять доступными на запись.

## 3. Как сохраняются A:G и технические данные

A: серверное время ISO; B: имя; C: телефон/Telegram; D: город; E: работа; F: `mypage / <requestId>` (источник с маркером для восстановления); G: Новая. Новые записи — literal text с number format @ и апострофом, формулы не исполняются. Существующие строки/форматы не переписываются. При последующих CSV-экспортах нельзя снимать текстовую защиту и затем импортировать пользовательский текст как формулы.

Отдельный журнал: request_id, HMAC полного содержимого, fingerprint, created, target_row, payload_b64, consent_at, privacy_version, state, telegram_status, attempts, next_attempt, last_code. Boolean согласия содержится также в кодированном payload. **Base64 не шифрование:** лист содержит PII, не публиковать, применять те же права и срок хранения. consent_at — время получения согласия сервером, не время клика пользователя.

Порядок: ScriptLock → восстановить PREPARED → проверить UUID/повтор контакта+города+работы за 24 часа → записать PREPARED + фиксированную строку → flush → записать A:G в фиксированную строку → flush → SAVED → flush → вернуть квитанцию. Если любая операция закончилась неопределённо, ответ не успешный; повтор того же UUID читает журнал и восстанавливает ту же строку. Повтор не делает appendRow в Лист1. Отсутствие транзакций между листами компенсируется журналом; это не Google SQL transaction.

**Операционное условие:** все сторонние скрипты записи должны использовать тот же ScriptLock, физическая сортировка/удаление/вставка строк во время PREPARED запрещена. Использовать filter views. При чужих изменениях целевой строки — ROW_CONFLICT и ручной разбор, не перезапись. Если перенести Лист1 в другую таблицу/менять строки вручную, журнал перестаёт гарантировать адресацию. Не менять signing secret до завершения старых запросов: меняются digest/fingerprint. >10000 строк журнала — fail closed/MAINTENANCE, требуется контролируемая очистка/архивация по сроку хранения и проверка PREPARED. Для очень большого потока нужен полноценный backend, а не линейный скан Apps Script.

## 4. Telegram outbox

doPost НЕ вызывает Telegram: успех означает сохранение Sheet, а не доставку уведомления. После отдельного подтверждения включить MYPAGE_NOTIFICATIONS_ENABLED и в Apps Script: Триггеры → Добавить → retryTelegram → По времени → Каждые 5 минут. Максимум 5 уведомлений/вызов, 10 попыток; экспоненциальная задержка от 5 минут до суток. Попытка фиксируется ДО сети. Неудачи/timeout оставляют pending, после лимита — needs_review. Владелец контролирует pending/needs_review и после проверки может обнулить attempts/next_attempt для конкретной записи. Успех Telegram отмечается sent, заявка повторно не записывается.

Отправка at-least-once: Telegram мог принять сообщение до потери ответа, поэтому возможен повтор с тем же UUID. Строгого exactly-once у sendMessage нет. Квоты/время Apps Script могут прервать обработчик; next_attempt не даёт мгновенного повторного цикла. Остановка публичного приёма не останавливает очередь автоматически — для этого отдельный флаг. Telegram-секрет не находится в Worker/браузере.

## 5. Cloudflare: бесплатные ресурсы, только действия владельца

1. В Cloudflare выбрать Workers Free, не подключать платный тариф. Turnstile → Add widget → hostname ivanzdaniekin.github.io, action candidate. Site key публичный, secret только в Worker. Не использовать тестовые ключи Turnstile в production.
2. Workers & Pages → D1 → создать бесплатную базу. SQL Console: выполнить backend/schema.sql. В Worker привязать D1 как DB. Не хранить поля заявок или IP в D1; код сохраняет только псевдонимные HMAC, UUID, квитанции и время.
3. Скопировать backend/wrangler.toml.example в backend/wrangler.toml (игнорируется Git), указать D1 ID и /exec URL. С помощью официального Wrangler (установка владельцем, без изменений платного тарифа) развернуть backend/worker.mjs. Настройки Worker Variables/Secrets: ENABLED=false, PRIVACY_APPROVED=false, TEST_ONLY=true, PRIVACY_VERSION; APPS_SCRIPT_URL. Secrets: TURNSTILE_SECRET, SIGNING_SECRET, независимый HASH_SECRET (>=32 случайных байт), TEST_KEY (>=32 символа).
4. Cron `0 3 * * *` удаляет только D1 buckets/receipts. Настроить отсутствие logging payload, проверить квоты Free. Скрипт приложения не пишет PII/секреты; не включать body logging у провайдеров.
5. TEST_ONLY=true требует X-Mypage-Test-Key ДО всех проверок/внешних вызовов. Этот дополнительный серверный секрет НЕ помещается в assets/leads-config.js. Поэтому владелец может провести приватный тест, не открывая публичный приём. Клиентский CORS не считается защитой от ботов.

## 6. Проверка реального контракта без записи

После ручного развёртывания Apps Script с MYPAGE_ENABLED=false, MYPAGE_ALLOW_PROBE=true владелец локально задаёт APPS_SCRIPT_URL и MYPAGE_SIGNING_SECRET через защищённую среду (не аргументы командной строки, не Git, не чат). Запуск:

`node tests/live-contract-probe.mjs --allow-remote`

Проверяет фактический doPost, HMAC тела, Google ContentService redirect и JSON с `protocol=mypage-v2`, nonce, saved=false. Не пишет Sheet, не отправляет Telegram. Это единственный реальный сетевой probe, но **здесь он не запускался**: URL и доступ не предоставлены. В ответах Apps Script HTTP 200 может означать отказ; Worker смотрит JSON protocol, saved и requestId. Redirect разрешён только HTTPS script.googleusercontent.com и без пересылки подписанного тела на GET. HTML страницы входа/ошибки не считаются успехом.

## 7. Ровно один приватный сквозной тест — ТОЛЬКО после отдельного подтверждения

1. Сначала получить подтверждение владельца на одну синтетическую запись и Telegram-уведомление. По умолчанию НЕ запускать. Лучше отдельная тестовая Google Таблица и группа. LEADS_TEST_MODE можно оставить disabled: тест через подписанный Web App, не через testLead.
2. В тестовом Apps Script включить MYPAGE_ENABLED=true, но доступ к нему защищён HMAC, URL не размещён на сайте. Worker оставить TEST_ONLY=true, затем ENABLED=true и PRIVACY_APPROVED=true только для синтетики с согласованной тестовой версией. Без TEST_KEY Worker продолжает отвергать запросы, публичная форма всё ещё disabled. Уведомления false до явного разрешения.
3. В локальном окружении владельца задать WORKER_ENDPOINT=https://<worker>.workers.dev/applications, TURNSTILE_SITE_KEY, PRIVACY_VERSION, MYPAGE_TEST_KEY. Установить локальный Playwright из официального реестра при необходимости. Запустить `node tests/live-owner-test.cjs --allow-one-live` (при нестандартном пути установить NODE_PATH/CHROME_PATH).
4. Откроется отдельный Chrome с локальной подменой файлов сайта на его origin. Это НЕ deployment и не изменение GitHub Pages. Поля заполнены только Synthetic Candidate / @synthetic_candidate / Synthetic City / Synthetic job. Самостоятельно пройти Turnstile, отметить тестовое согласие и нажать Отправить ОДИН раз. Код не отправляет автоматически, блокирует второй POST и любые другие значения полей. TEST_KEY добавляется только из процесса локального теста, не в публичный JS.
5. Проверить одну строку Лист1, SAVED в журнале, consent/version/time, затем после подтверждения группы включить MYPAGE_NOTIFICATIONS_ENABLED и вручную вызвать retryTelegram один раз. Проверить одно сообщение с тем же UUID и sent. После проверки сразу выключить оба Apps Script флага, Worker ENABLED=false/PRIVACY_APPROVED=false; TEST_ONLY оставить true. Очистить синтетические данные вручную после проверки.
6. Для live параллельных/повторных/signed-negative тестов необходимо отдельное разрешение на дополнительные попытки; одиночный тест не доказывает все облачные сценарии. Локальные тесты уже моделируют повторы, lock contention, ложный секрет, consent, формулы, неизвестный результат и отказ Telegram. В тестовой группе owner должен отдельно подтвердить реальное поведение при отказе/восстановлении, если это требуется как критерий запуска.

Без реальных endpoint и такого подтверждения честный статус: код готов к развёртыванию, реальная цепочка НЕ проверена. Не ставить отметку «работает» на основании mocks.
